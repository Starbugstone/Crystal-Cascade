# Analysis and verification — September 2026

The prototype's sluggishness came primarily from animation sequencing, renderer reactivity and input handling. The match scan itself is small for a 72-cell board. The old UI also devoted substantial space to debug tools and loaded oversized prototype graphics.

## Findings and changes

| Area                | Finding                                                                                                                 | Change                                                                                                                                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Renderer            | Phaser Game was held in a deep Vue ref and its scene, animator and input objects entered a reactive Pinia object graph. | Plain local Game instance; `markRaw` at the renderer and audio boundaries.                                                                                                                              |
| Cascades            | Existing gems fell for 400 ms, followed by a separate 400 ms refill.                                                    | Both run in the same 202–250 ms phase, with a 90 ms match pop.                                                                                                                                          |
| Gestures            | A swipe only committed on release; long drags could point at a nonadjacent cell.                                        | A 22% cell displacement commits to the immediate neighbor, once per gesture. Tap selection, touch cancellation and keyboard controls are supported.                                                     |
| Input races         | Invalid swaps did not hold the animation lock. Queued powers retried through timers.                                    | Rejections use the same lock; one buffered action drains at phase completion.                                                                                                                           |
| Session lifecycle   | Animation continuations could commit after exiting or replacing a level. Destroyed tweens could leave promises waiting. | Session version guards reject stale results; clearing the renderer settles every pending tween promise.                                                                                                 |
| Resizing            | Fullscreen scheduled three redraws and synthetic resize events.                                                         | One coalesced ResizeObserver path; layout changes wait until moving sprites settle.                                                                                                                     |
| Hints               | Every candidate simulated random cascades, allocated refill gems and consumed random numbers.                           | Deterministic evaluation of immediate matches, bonuses and tile damage. Playability checks stop at the first move. Frozen swaps are excluded.                                                           |
| Starting boards     | Random generation allowed preexisting matches, which made unrelated swaps appear valid.                                 | Generation excludes completed runs and verifies legal starting moves.                                                                                                                                   |
| Cascade termination | A fixed RNG could generate an endless refill loop, hanging an existing test.                                            | Pathological chains switch to match-avoiding refills, with a hard termination guard.                                                                                                                    |
| Particle effects    | Every spark allocated a shape and a tween.                                                                              | Two pooled emitters cap sparks at 320 and ice shards at 128. Decorative objects are capped at 160; only six specials in a chain receive full impact effects. Cosmetic tails do not delay gravity.       |
| Graphics            | Inconsistent large sprite sheets required manual crop offsets; pixel-art mode made scaled gems rough.                   | Six faceted gems, three animated bonus icons in one atlas, five illustrated powers, and two ice stages: 85.6 KB of SVG artwork in total. Rasterized once; no runtime SVG drawing in the animation loop. |
| Interface           | Debug redraw/lootbox controls, empty rails and duplicated fullscreen controls dominated the game.                       | A collection screen, compact score/objective HUD, framed board, power toolbar, responsive layout, native modal dialogs and focus mode.                                                                  |
| Accessibility       | Reduced-motion/high-contrast switches were not connected to rendering.                                                  | Preferences affect board movement, particles, effects, outlines and CSS. System reduced-motion preference is respected. Native dialogs contain focus and support Escape.                                |
| Audio               | Effects were first requested at the moment they played.                                                                 | Sounds warm up when entering a level; cascade pitch rises gently with the chain. Music now uses the slider's full range, removing the extra 35% volume cap.                                             |
| Dependencies        | The installed lockfile reported 12 advisories.                                                                          | Compatible updates and unused dependency removal; final audit reports zero.                                                                                                                             |

## Animation budget

These are configured durations, not hardware benchmarks. Browser scheduling and additional cascade stages increase elapsed time.

| Phase                                      | Before                               | After                                                                          |
| ------------------------------------------ | ------------------------------------ | ------------------------------------------------------------------------------ |
| Swap                                       | 180 ms                               | 115 ms                                                                         |
| Invalid swap, out and back                 | 240 ms                               | 150 ms                                                                         |
| Drop plus refill                           | 800 ms sequential                    | 202–250 ms together                                                            |
| A normal single-stage move, including swap | About 980 ms                         | About 407–455 ms                                                               |
| Full 8 × 9 board introduction              | Up to 1,541 ms                       | Up to 436 ms                                                                   |
| Rainbow activation                         | Serial delays grew with every target | 120 ms wind-up, then simultaneous lightning; visual tails do not delay gravity |

The visual direction uses violet glass, warm gold details and six distinct gem silhouettes. Uncleared tiles use translucent frosted glass with soft reflections and subtle edges, with contrasting branching cracks on damaged layers; the last hit releases shards and exposes a dark tile. Bonuses have recognizable animated silhouettes: a sparking bomb, a rotating rainbow orb and a pulsing four-way launcher. A brief wind-up precedes layered shockwaves, directional blasts or rainbow lightning, with arcade callouts. Toolbar powers use illustrated icons and effects originating at the selected target or actual cleared row. Reduced motion stops bonus loops, removes these flourishes and shortens clears and falls.

## Verification

- Production build and all 33 Node-based Vitest tests pass. Regression coverage includes settled level generation, deterministic hints, pathological RNG termination, input bounds, swipe timing, pointer jitter, multiple pointers, tap selection, raw renderer objects, cancelled tweens, stale session results and rejected-swap buffering. Additional bonus tests cover accurate activation footprints, toolbar origin metadata, cancelling a special during its wind-up and reduced-motion behavior.
- Chromium checks at 1440 × 1000 and 390 × 844: collection, gameplay, compact board, score/objective updates, settings, reduced motion, keyboard, all five powers, focus mode and replay.
- Twenty consecutive desktop mouse moves completed, including a five-stage cascade. Every cell's sprite ID and final position matched board state after every move. The renderer held exactly 72 gem sprites and zero pending tween promises at the end. No application runtime errors were captured.
- The swipe probe confirmed an active move before pointer release. A separate Chromium touch-emulation probe dispatched real touch events and confirmed the same behavior.
- A compact chapter completed through 25 legal moves. The victory dialog appeared, and replay restored score/moves to zero and all 50 tile layers.
- Exiting during an active swap and immediately opening the compact chapter left 25 correct sprites, zero score and zero moves in the new session.
- Production checks at 1365 × 768 and 390 × 844 confirmed that the board and power controls fit the viewport. At 320 × 568, the game and collection have no horizontal overflow. No failed requests or runtime errors were recorded, and the collection did not request the deferred Phaser chunk.
- The bonus/ice revision was checked at 1440 × 1000 and 390 × 844. All three on-board bonus loops advance through atlas frames; reduced motion stops them at frame zero and turning it off resumes them. Real mouse swipes activated each bonus, with exactly 72 aligned sprites, correct remaining ice counts and no pending tweens after effects settled. All five illustrated toolbar powers consumed one use and completed successfully on the mobile layout, whose controls fit within 844 pixels. No runtime errors were captured.
- Twelve further moves with the new ice and effects produced no sprite drift, with peaks of 34 decorative objects and 168 live particles. A board filled with chained bonuses settled successfully and peaked at 109 decorative objects, below the cap of 160. Changing chapters during a bonus wind-up left the new chapter at zero score/moves, with 25 sprites and zero pending tweens. The mobile-viewport frame sample recorded a 16.7 ms median and 33.3 ms 95th percentile in headless Chromium.
- Browser screenshots are under the ignored `output/playwright/` directory, including `ice-and-bonuses-desktop.png`, `ice-and-bonuses-mobile.png` and `bonus-{bomb,cross,rainbow}-activation.png`.

The desktop run sampled a 16.7 ms median animation frame and a 33.4 ms 95th percentile in this headless Linux browser. The browser used software graphics and reported driver `ReadPixels` warnings around captures. These measurements are evidence of this environment only; they are not a promise of sustained 60/120 fps on physical devices.

## Remaining limits

The Phaser engine remains a substantial deferred download, approximately 332 KB gzipped in the verified build; Vite emits a size warning for this chunk. The initial app script is approximately 63.5 KB gzipped. Real iOS/Android hardware, native Capacitor builds, Safari and Firefox were not verified here. Progress, inventory and settings remain session-local, matching the prototype's persistence model. Scoring and automatic reshuffle penalties are retained and could benefit from a separate balance pass.
